# 온리프라이버시 / OnlyPrivacy 0.3.0

<img src="assets/logo.png" width="120" alt="OnlyPrivacy Ps logo">

**공개 시험망과 전용 Mac 지갑.** [공개망 참여 안내 / Public testnet](PUBLIC_TESTNET.md) · [일반 지갑 연동 상태](integrations/wallets.md)

독립 체인에서 비공개 송금, 투명한 영지식 STARK 검증, ML-KEM 수신 노트 암호화, CPU 작업증명 채굴을 연결한 연구 구현입니다. 이더리움이나 ERC-20을 사용하지 않습니다. 라이선스는 GPL-3.0-or-later이며 외부 라이브러리의 라이선스는 각각 유지합니다.

현재 로컬 Mac ARM64에서 실행·검증했습니다. 실제 소유자 100 ONLYP는 소스와 분리된 암호화 지갑에 보관했습니다. 9,900 ONLYP의 채굴 준비금에는 개인 지갑이나 관리자 개인키가 없습니다. 시장 가격이나 거래소 상장은 설정되어 있지 않습니다.

## 이 컴퓨터에서 시작

상위 폴더의 `온리프라이버시.command`를 여세요. 개인 지갑은 상위 `온리프라이버시_내지갑_100개/내지갑.command`에서 엽니다. 프로그램은 비밀번호를 명령행에 넘기거나 화면에 표시하지 않습니다. 운영체제가 키체인 접근을 요구하면 본인이 허용해야 합니다.

- `채굴시작.command`: Tor를 준비하고 별도 참여 지갑과 채굴 메뉴를 엽니다. 채굴은 사용자가 선택할 때 실행합니다.
- `노드공유.command`: 로컬 검증 노드와 Tor onion 서비스를 실행합니다. 노드 주소를 직접 참여자에게 전달할 수 있습니다. Ctrl+C로 함께 종료합니다. 개인 지갑을 열 필요가 없습니다.
- 개인 지갑의 송금 메뉴는 먼저 거래 파일을 만듭니다. 노드에 제출한 거래가 유효한 블록에 포함되어야 확정됩니다. 블록 높이 기준 64블록이 지나면 거래를 다시 만들어야 합니다.
- 새 받는 주소는 새 소유권 비밀과 ML-KEM 키를 사용한 일회용 주소 파일입니다. 재사용하지 말고 송신자에게 전달하세요. 안정적으로 재사용할 수 있는 일반 지갑 주소 체계는 현재 제공하지 않습니다.
- 오래 보관한 코인은 `갱신 거래 만들기`로 현재 지원 스위트의 새 출력에 옮깁니다. 복사하여 새 코인을 생성하지 않습니다. 최대 2개 입력 노트씩 처리하고 일반 거래 수수료를 냅니다.

공개 시험 시드는 `config/peers.json`에 있습니다. 실제 Tor 연결을 확인했습니다. 초기 시드는 한 컴퓨터에서 운영되며, 이 컴퓨터와 프로그램이 켜져 있을 때 접속할 수 있습니다. 독립 운영자 다수가 운영하는 상시 공개망과는 운영 조건이 다릅니다. 자세한 참여·채굴 방법은 [PUBLIC_TESTNET.md](PUBLIC_TESTNET.md)에 있습니다.

## 통화량과 보상

| 항목 | 규칙 |
| --- | --- |
| 단위 | ONLYP, 소수점 12자리 |
| 최초 총배정 | 10,000 ONLYP |
| 최초 개인 지갑 | 100 ONLYP |
| 최초 프로토콜 채굴 준비금 | 9,900 ONLYP |
| 준비금 분배 | 120초 목표 블록, 목표 10 × 365일, 실제 경과 체인시간과 남은 준비금으로 제한 |
| 별도 신규 발행 | 목표 연 100 ONLYP, 체인 타임스탬프에 따른 누적·이동 365일 상한 검사 |
| 보상 | 유효한 블록 채굴자에게 해당 블록의 준비금 해제분 + 신규 발행분 + 수수료 전부 |
| 수수료 | 일반 송금·갱신당 0.000001 ONLYP |

이상적인 목표 속도에서 t년 후 총량은 `10,000 + 100t`, 신규 발행률은 `100 / (10,000 + 100t)`로 0에 가까워집니다. 지연·블록 속도에 따라 실제 신규 발행은 목표보다 작을 수 있습니다. 분배가 지연된 준비금은 목표 블록 수가 지난 뒤에도 잔액 한도 내에서 계속 지급합니다.

준비금은 최초 총량에 포함되어 있어 그 해제는 신규 발행이 아닙니다. 그러나 최초 유통량은 100개이므로 준비금 분배 기간의 **유통량 증가율은 연 1% 이하가 아닙니다.** 목표 속도에서 첫해 유통량은 약 1,190개입니다. 수요를 이유로 통화 규칙이 자동 변경되지 않습니다. 채굴 보상은 신원·인원수 기준 균등 배분이 아니라 성공한 작업증명에 비례합니다.

## 개인정보와 규칙

소유권·입력 소속·금액 합계·금액 범위·잠금·중복 지출 방지를 고정된 영지식 프로그램이 검사합니다. 수신 노트의 상세 내용은 ML-KEM-1024, HKDF-SHA256, AES-256-GCM으로 암호화하고 새 수신 키를 사용합니다. 외부 요청은 인증 분리가 있는 Tor SOCKS를 통해 v3 onion 주소에만 전송하며 직접 인터넷 연결로 우회하지 않습니다.

공개 장부에는 블록, 작업증명, 영지식 증명, 커밋먼트, 중복 지출 검사용 nullifier, 암호문, 공개 수수료와 발행 규칙이 남습니다. 수신자 지갑은 본인 출력의 금액과 내용을 복호화합니다. 송신자가 상대의 모든 거래 내역을 열람하는 기능은 없습니다. 장부 전체를 숨겨 검증을 불가능하게 만드는 방식은 채택하지 않았습니다.

개발자용 동결·회수·임의 발행·전체 복호화·강제 업데이트 키가 없습니다. 누구나 코드를 고치고 다른 체인을 만들 수 있지만 기존 노드는 자신이 채택한 제네시스와 규칙에 맞지 않는 블록을 거부합니다. 현재 네트워크는 등록된 수신 스위트 중 2번으로 시작합니다. 아직 등록되지 않은 미래 알고리즘, 증명 체계, 통화 규칙은 검토된 코드와 참여 노드의 채택이 필요합니다. 임의 코드를 자동 다운로드해 실행하지 않습니다.

## 검증 및 개발

현재 54개 시험에서 실제 증명 생성·변조 거부·독립 재검증·별도 채굴자 지급·저장 장애·Tor 전송 규칙·지갑 복사 중복 지출 거부 등을 확인했습니다. [검증 결과](reports/검증결과.md), [프로토콜](PROTOCOL.md), [보안과 남은 과제](SECURITY.md), [빌드 방법](BUILD.md)을 함께 보세요.

전체 코인의 양자내성을 수학적으로 증명했거나 독립 감사를 마친 상태는 아닙니다. 실제 공격자·침해된 컴퓨터·거래 상대·전 세계 트래픽 관찰자로부터 무조건적인 익명성을 보장하는 시험도 아닙니다. 일반 지갑 직접 지원, 거래소 입금, 임의의 미래 보안 규칙으로 자동 변환하는 기능은 완료되지 않았습니다.

## 전용 지갑과 암호학적 주소

`OnlyPrivacyWallet.app`은 macOS 14 이상 Apple Silicon용입니다. 새 사용자는 비밀번호를 정해 초기 잔액 0의 참여 지갑을 만들고, 잔액·일회용 주소/QR·송금 준비·Tor 제출·동기화·코인 갱신을 사용할 수 있습니다. UI 소스는 `wallet/macos/`이며 `node scripts/build-wallet.mjs`로 빌드합니다. 검정 바탕의 큰 금색 P 안에 작은 s를 넣은 로고를 사용합니다.

주소는 매번 새 비밀값과 ML-KEM 공개키로 생성합니다. `onlyprivacy:v1:` 형식에 네트워크 구분과 SHA3-256 기반 체크섬을 넣어 오타·다른 체인·잘못된 공개키를 거부합니다. 주소·QR에는 개인키와 비밀번호가 들어가지 않습니다. 일반 메타마스크·트러스트월렛 지원은 아직 없으며, 실제 100개를 일반 EVM 주소로 보낼 수 없습니다.
